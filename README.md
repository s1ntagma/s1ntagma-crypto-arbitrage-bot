# latbot - терминал межбиржевого лага

Бот следит за несколькими биржами по WebSocket, ловит момент, когда одна биржа уже сдвинулась,
а другая ещё отстаёт, и показывает **реально исполнимую** возможность: купить и продать
**на одной и той же (отстающей) бирже**, пока лаг существует. Никаких переводов между биржами.

Главный процент - только **NET** (после комиссий, спреда, проскальзывания, потерь на исполнение,
на том размере, который стакан реально держит). Нет edge - нет сигнала.

Для каждой возможности две независимые оценки - **HUMAN** (успеет ли человек за
`HUMAN_EXECUTION_TIME`) и **BOT** (успеет ли API-бот с текущими задержками) - светофором
🔴 🟡 🟢. Решение - за тобой: **[ MANUAL ]** (бот ведёт тебя по шагам) или **[ AUTO ]**
(бот исполняет сам после финальной перепроверки).

В UI видны все реальные возможности (0.3 %, 1 %, 7 %…). В Telegram уходят только
исполнимые с NET >= 3 % (порог настраивается).

## Что показывает карточка

Каждая возможность — это план сделки на твоей бирже, по-русски:

```
🏃 ZK · догоняющая без перевода · NET +2.43% (+€2.43 на €100) · держится 24 мин 13 с
Revolut X двинулась первой: +2.2%; Kraken пока +0.3% · разрыв 1.9%
1. Купить на Kraken ZK/EUR ≤ 0.0112291 EUR (сейчас 0.0109631 EUR) · сумма до €100
2. Не переводить. Продать там же на Kraken, когда догонит: ≥ 0.0114109 EUR (цель с учётом издержек)
Окно по этой монете: ~2 мин 48 с · догнала 0 из 32 · человек успевал 3 из 10
! Kraken может не догнать: объём на Revolut X мал. Не догнала за ~1 мин — продай по рынку.
обновлено 12:41:10
```

Плюс кнопка **Open on Kraken** прямо на страницу пары, светофоры HUMAN/BOT, таймер окна и кнопки MANUAL / AUTO.
«Купить ≤» — предел, выше которого сделка перестаёт быть плюсовой после комиссий; «Продать ≥» — цель выхода с учётом издержек.
Тот же текст уходит в Telegram при NET ≥ 3 %, если успевает человек.

Вверху вкладки «Opportunities» — лучшая возможность с **графиком лага**: реальные цены бирж,
которые двинулись (синие линии), и твоей биржи (зелёная), в % за последние 15 / 30 / 60 с.
Пунктир — момент, когда бот увидел сигнал. Нет цен — нет линии (ничего не дорисовывается).
Над графиком — плашка «Live monitoring»: сколько бирж реально на связи и сколько открытых возможностей.

Биржи-цели (где покупаешь и продаёшь): Kraken, Coinbase, Bitvavo, Bitstamp, Crypto.com, OKX EEA, Bybit, Gate, Revolut X (только REST: цены опросом, стакан по запросу).
Источники сигнала «рынок двинулся»: Binance, KuCoin, MEXC, Bitget, HTX. Сигнал появляется, только если двинулись минимум две биржи, а твоя ещё нет.

## Быстрый старт (Windows, без Git)

1. Скачай архив ветки: https://github.com/s1ntagma/s1ntagma-crypto-arbitrage-bot/archive/refs/heads/claude/elegant-newton-g91gip.zip
   (или на GitHub: зелёная кнопка **Code → Download ZIP**).
2. Распакуй в любую папку, например `Documents\latency_bot` (внутри должны лежать `start.bat`, `run.py`, папка `latbot`).
3. Запусти `start.bat`. При первом запуске он сам: проверит Python 3.11+, поставит зависимости,
   создаст `.env` и откроет его в Блокноте. Вставь токен бота после `TELEGRAM_BOT_TOKEN=`, сохрани, закрой Блокнот.
4. Через несколько секунд откроется терминал `http://127.0.0.1:8787`. Остановка - `stop.bat`.
   Ярлык на рабочий стол - `shortcut.bat`.

**Сделки и статистика сохраняются.** База лежит не в папке программы, а в `%LOCALAPPDATA%\latbot`
(обычно `C:\Users\<имя>\AppData\Local\latbot`). Поэтому выключение и включение бота, а также новая версия
в новой папке ничего не обнуляют. При первом запуске новой версии бот сам забирает:
* историю из самой свежей прежней папки (`data\latbot.sqlite3`);
* `config.json` и `.env` из прежней папки, если в новой их нет.
Счётчики (сколько открыто и закрыто сделок, в том числе тренировочных) тоже хранятся в базе.
Позиции, открытые в момент выключения, закрываются как «нет данных»: результат не выдумывается.
Своя папка для базы — `db_path` в `config.json` или переменная `LATBOT_HOME`.

Нет Python - поставь с https://www.python.org/downloads/windows/ с галочкой «Add python.exe to PATH».
Старый бот с тем же Telegram-токеном перед запуском выключи (Telegram не даёт двум программам один токен).

## Запуск (Windows)

1. Python 3.11+. В папке проекта: `pip install -r requirements.txt`.
2. Скопируй `.env.example` в `.env`, впиши токен Telegram и ключи бирж
   (Bybit - ключи **Demo Trading**; права только торговля, без вывода).
3. `start.bat` - запускает и сам перезапускает бота. `stop.bat` - останавливает.
4. Открой `http://127.0.0.1:8787` - терминал. Все настройки меняются там (шестерёнка) и сохраняются в `config.json`.

Проверка без ключей: `python run.py 10` (10 секунд работы, потом выход; то же самое -
`python -m latbot 10`). Коды выхода: 0 - штатная остановка, 3 - бот уже запущен
(`logs/bot.lock`), иначе - сбой (`start.bat` перезапускает).

## Режимы

- **PAPER** (по умолчанию): виртуальный баланс (`PAPER_BALANCE`), сделки имитируются по живому стакану
  с комиссиями, проскальзыванием, задержкой и частичным исполнением. Bybit в этом режиме может работать
  через Demo Trading (`paper_engine = "bybit_demo"` в `config.json`).
- **LIVE**: реальные ордера через API на биржах, где есть ключи. Включается только явно
  (`MODE=LIVE` в `.env` или переключатель в настройках). UI всегда показывает, какой режим активен.

Путь: BACKTEST -> PAPER на живых данных -> LIVE на маленьком капитале -> проверка -> масштаб.

## Диагностика: почему нет сигналов

Пустая доска - не «всё хорошо» и не «всё сломано», а вопрос. Вкладка **DIAG** (и команда `/diag` в Telegram)
показывает воронку: бирж подключено, монет сканируется, тиков получено, движений замечено, кандидатов
отброшено (по какой причине: одна биржа, объём, нет свежих данных, лаг меньше порога, стакан, NET после
комиссий, ликвидность), сигналов прошло, возможностей, алертов. И прямо пишет, на каком этапе воронка
пустеет и какая настройка за это отвечает. Каждая причина - с последними монетами.

**Битые стаканы.** Иногда после обрыва связи у биржи в стакане остаются старые цены с одной стороны, и
покупка выглядит дешевле продажи (bid ≥ ask) — на настоящей бирже так не бывает.  Бот такой стакан не
использует (нет цены = нет сделки), сразу берёт свежий стакан через REST и переподписывается; колонка
**Crossed** в DIAG показывает, сколько таких стаканов пришло.  Битым считается и стакан, в котором сделка прошла выше лучшей цены продажи или ниже лучшей цены покупки, а стакан не двигается: сквозь один и тот же уровень прошло ≥ 3 сделок за ≥ 2 с, и он всё ещё стоит на месте — значит, его давно не существует.  Одна сделка сама по себе ничего не доказывает: лента сделок обычно опережает стакан, а в быстром рынке уровни тут же перезаполняются.  Кроме того, на биржах, где библиотека умеет переподписываться на стакан, бот делает это раз в 5 минут (`ws_book_resubscribe_s`), чтобы старые уровни не пережили тихие переподключения.  Сборка с этой защитой один раз начинает
новый период Stats: старые виртуальные сделки могли быть посчитаны на битых стаканах (история остаётся
в базе).

## Ручная сделка: от «Я ЗАШЁЛ» до результата

На карточке нажми **Я ЗАШЁЛ** - экран целиком переключается на эту одну сделку (остальные возможности
не теряются и обновляются под ней, сверху счётчик «ещё N на доске»):

1. **Сумма**: сколько вложить (быстрые кнопки, «макс. стакана»).
2. **Точный план** на эту сумму по реальному стакану: сколько купить, по какой цене (≤ предел и цена сейчас),
   сколько потом продать, по какой цене (≥ цель), ожидаемый NET и прибыль. Кнопка **ОТКРЫТЬ БИРЖУ** ведёт прямо на пару.
3. **Я КУПИЛ**: впиши реальную цену и сумму.
4. **Сопровождение**: бот каждые 0,3 с сверяет стакан с целью и пишет прямым текстом:
   «ЖДИ», «ПРОДАВАЙ СЕЙЧАС» или «продай по рынку» (окно закрылось / лаг исчез) и показывает, сколько получишь, если выйти сейчас.
5. **Я УШЁЛ СО СДЕЛКИ**: цена выхода, итог по бирже (необязательно) и заметка.
6. Результат сохраняется в базе рядом с ожидаемым (в том числе «успел ли в окно» и время до покупки);
   по накопленным сделкам бот корректирует оценку «успевает ли человек». Через 8 секунд (или по кнопке
   «К МОНИТОРИНГУ») бот возвращается к поиску следующей сделки.

Открытую сделку можно свернуть - она остаётся на карточке и возвращается на экран после перезагрузки страницы.

## Простой режим (включён по умолчанию)

Логика одна: монета выросла на бирже, где её торгуют больше всего (лидер по обороту за 24 ч, обычно
Binance), а на твоей бирже ещё нет — бот показывает покупку на твоей бирже и продажу, когда она догонит.

* **Лидер** — одна биржа-источник с самым большим оборотом по этой монете. Движение других бирж
  сигналом не считается.  На биржах-источниках бот смотрит их основной рынок — к USDT
  (`signal_quote_assets`), а на твоих биржах торгует к EUR (`quote_assets`).  До сборки с этим
  исправлением биржи-источники брали тонкий рынок к EUR/USDC (у Binance BTC/EUR в 200 раз меньше
  BTC/USDT), и лидером ошибочно становились HTX или KuCoin; поэтому статистика один раз начинается
  заново, а выученный догон сбрасывается (он был измерен против неправильного лидера).
  Если поток цен биржи молчит дольше 10 с (`ws_silent_s`), бот берёт её цены из опроса раз в 2 с, а
  лидером может быть только биржа со свежими ценами (молчащий Binance уступает следующей по обороту).
* **Вход и удержание** — по умолчанию по правилам «Езды за лидером» (ниже): вход, пока лидер не откатил
  от своего пика, но не позже 60 с; выход по развороту лидера / догону / трейлингу / стопу, страховка 5 мин.
  Если «езду» выключить в Настройках, действуют жёсткие лимиты: вход только в первые
  `simple_entry_deadline_s` = 3 с, удержание максимум `simple_max_hold_s` = 15 с.
* **Оценка качества, новости, макро** — только информация (значок «Quality … (info)»), ничего не блокируют.
* **Не отключается никогда**: свежие данные, NET после комиссий и проскальзывания на реальном стакане,
  перепроверка перед ордером, лимиты риска.
* На карточке строка: «Binance moved, lag +0.62% · expected catch-up … · fees + execution 0.80% · NET …».
  Если комиссии больше лага — возможности нет. Комиссия «туда-обратно» (taker): Revolut X 0.18 %,
  Bybit EU и OKX EEA 0.2 %, Gate 0.4 %, Bitvavo 0.5 %, Kraken 0.8 %, Coinbase 1.2 %, Crypto.com 1.5 %.
* Выключить: Настройки → Simple mode (тогда работает полный режим: 2 биржи, оценка качества как фильтр).

### Езда за лидером (включена в простом режиме)

Не продавать за секунды, а держать, пока лидер растёт, и продавать, когда его движение закончилось.

* **Вход** — пока лидер не откатил от своего пика больше чем на 0.3 % и прошло не больше 60 с с начала
  движения. Лидер развернулся — вход закрывается («leader reversed» в DIAG).
* **Выход** — первое сработавшее правило:
  1. стоп: −1 % на позиции;
  2. лидер развернулся: откат 0.3 % от его пика;
  3. твоя биржа догнала (разница ≤ 0.1 %) и лидер 5 с не делает новый максимум — забираем прибыль;
  4. трейлинг: прибыль была ≥ 0.3 % и откатилась на 0.3 % от пика;
  5. страховка: 5 минут.
* Одни и те же правила у виртуальных сделок (Stats → Exits: по каким причинам закрывались), в ручной
  сделке (экран сопровождения: «ДЕРЖИ — лидер ещё растёт» / «ПРОДАВАЙ СЕЙЧАС — лидер развернулся») и в AUTO
  (после покупки бот сам следит и продаёт одним рыночным ордером).
* Основные числа — в Настройках, блок Simple mode; остальные (`ride_lag_closed_pct`, `ride_stale_s`) — в `config.json`.  Гарантий нет: правила фиксируют большую часть движения,
  но пик заранее не знает никто.  Проверяйте на виртуальных сделках (Stats) прежде чем включать AUTO.

## Только проверенные пары, тренировка, готовность к реальным деньгам

Прибыль «наверняка» в сделке на лаге невозможна: продажа всегда в будущем. Поэтому «наверняка» — это
измерение: бот предлагает сделку только по паре «монета @ твоя биржа», которая сама доказала себя на
его виртуальных сделках текущей стратегии.

* **Проверенная пара** — не меньше 30 виртуальных сделок, «худший случай» доли побед (5-й перцентиль)
  не ниже 60 % и средний NET больше +0.05 %.  Только такие предложения видны на главной, идут в Telegram
  и в AUTO.  Остальные («Training n/30», «Failing») бот продолжает торговать виртуально, чтобы учиться;
  их можно увидеть галочкой «Show training / low quality».
* **Тренировка на неограниченных виртуальных деньгах**: каждое предложение виртуально исполняется на
  сумму, которая по реальному стакану даёт наибольшую ожидаемую прибыль в деньгах (строка «Best size on
  this book» на карточке).  Ордера не отправляются.
* **Stats → PAIRS**: по каждой паре — сделки, победы, худший случай, средний NET и статус.
* **Stats → READY FOR REAL MONEY?**: не меньше 200 виртуальных сделок за период, хотя бы одна
  проверенная пара, средний NET больше 0 с уверенностью 90 %, просадка не больше 5 % (сумма NET %),
  доля побед на проверенных парах не ниже 60 %.  Пока хоть одна строка «no» — реальные деньги рано.
* Основные пороги — в Настройках (сделки, «худший случай»); остальные (`proven_min_avg_net_pct`,
  `proven_quantile`, `ready_*`, `best_size_multipliers`) — в `config.json`.  New period считает пары заново:
  после него все пары снова в тренировке, пока не наберут 30 новых сделок.
* «Худший случай» — 5-й перцентиль доли побед (строгая оценка: вердикт перепроверяется после каждой
  сделки), и пара должна держать правило и на последних 30 сделках.
* **Тренировка на каждом сигнале** (`shadow_train_all_signals`, включено).  Сигнал, который модель
  отбросила из-за комиссий («fees» / «below min NET» в DIAG), бот всё равно виртуально «покупает» —
  один раз на одно движение лидера — и ведёт так же, как обычную сделку.  Такие сделки никогда не
  становятся предложением (нет карточки, Telegram, AUTO), не мешают виртуальной сделке по настоящему
  предложению, не входят в виртуальный баланс, READY и проверенные пары (их судят только по
  предложенным сделкам) и показаны отдельно: **Stats → TRAINING** — по бирже и монете: средний лаг, сколько из него цена на
  твоей бирже реально прошла («capture»), NET по модели и настоящий NET.  Зачем: без этого при нуле
  предложений бот ничего не измерял и не мог научиться.  Реальный «capture» обучает ожидаемый догон
  (среднее по последним сделкам, после 5 сделок пары), поэтому пара, которую модель недооценивала,
  получит предложения по измерениям, а пара, которая не догоняет, так и останется без них.

### Как включить AUTO (бот торгует сам)

1. Жди, пока в Stats **READY FOR REAL MONEY?** все строки «yes».  В LIVE бот не откроет ни одной
   сделки, пока READY = no (настройка «LIVE AUTO only when Stats READY says yes», включена по умолчанию).
   AUTO на реальных деньгах — только проверенные пары, в любом режиме.
2. Ключи — **только в `.env` на твоём ПК** (никому не присылай, в чат тоже).  На бирже создай ключ с
   правами «чтение + торговля», **без вывода**; если биржа даёт — привяжи ключ к своему IP.
   PAPER торгует во встроенном симуляторе по живому стакану; `paper_engine = "bybit_demo"` переводит на
   Bybit Demo только сделки на Bybit (ключи Demo Trading).  Для LIVE на Bybit в `config.json` у bybit
   нужно `"demo": false` и настоящие ключи.  Начинай LIVE с маленькой суммы.
3. Настройки → **AUTO limits**: бюджет на каждую биржу (`Kraken=200, OKX EEA=500, Bybit EU=0` — сколько
   бот может держать в открытых сделках на этой бирже, 0 = там не торговать; опечатка не сохранится,
   будет ошибка), общий лимит на биржу, дневной лимит убытка, число одновременных сделок.  Бот всё
   равно берёт не больше реального свободного баланса.
4. Включи **Autopilot** (там же) — бот сам открывает и закрывает сделки по проверенным парам (пока
   включено «Offer only proven pairs»), через те же проверки, что и кнопка AUTO: свежий стакан, лимиты
   риска, одна позиция на пару, READY для LIVE.  Карточку, которую ты взял руками (Я ЗАШЁЛ / AUTO),
   автопилот не трогает.  Без автопилота AUTO запускается только кнопкой.  Сначала включи его в PAPER
   и посмотри сделки в Trades.
5. EMERGENCY STOP в терминале или `/stop` в Telegram (с подтверждением) — запрещает новые сделки и
   снимает ордера.

## Топ-100 монет (по умолчанию с версии конфига 7)

Весь бот (latency и Basis) работает по **топ-100 монет мира по капитализации** (CoinGecko):
- исключены стейблкоины, обёртки, стейкинг-токены, золото/RWA, фан-токены;
- порог: капитализация от $100 млн, оборот от $5 млн в сутки (чтобы набрать 100 торгуемых монет);
- фильтры стабильности (корреляция с BTC, скачки, funding) выключены: `pool_stability_filters: false`;
- первые 50 монет идут по WebSocket (`ws_assets`), остальные через REST-тикеры с проверкой по стакану;
- Basis берёт те же 100 монет (`basis_top_n`) и подхватывает новые монеты пула на ходу.

Старый узкий пул вернуть: `"pool_stability_filters": true`, `"pool_max_assets": 25` в `config.json`.

## Узкий пул, качество сигнала, контекст рынка, плечо

**Меньше сделок — выше качество анализа.** Бот сканирует только узкий пул предсказуемых монет:
- топ по капитализации (от $1 млрд) и обороту (от $20 млн в сутки глобально, от 500 тыс. на твоей бирже);
- без мем/хайп-монет, стейблкоинов, обёрток (списки по ID CoinGecko);
- без монет, которые сейчас резко накачали/слили (24 ч > ±15 %, 7 дн > ±100 %);
- стабильные за 30 дней: часовая корреляция с BTC от 0.40 и не больше 20 собственных скачков ≥ 3 % в час;
- живой фильтр: 2+ минутных скачка ≥ 1 % за час или ≥ 3 % за 5 мин — новые сигналы по монете на паузе.

Пул и причины исключения видны во вкладке **Market** (внизу) и в DIAG.

**Оценка качества 0–100** у каждой возможности (значок `Quality 78 · B` на карточке, подробности в WHY):
выгода против издержек, сколько бирж двинулось и их объёмы, глубина стакана, история догоняния
этой монеты на этой бирже (и таблица исходов похожих ситуаций), стабильность реакции и 11 факторов
рынка: календарь США (CPI, PPI, NFP, безработица, ФРС), новости и Telegram-каналы (WatcherGuru,
WalterBloomberg, FinancialJuice, Whale Alert и др.), переводы китов, funding, открытый интерес,
ликвидации, режим BTC/ETH, фондовый рынок США и DXY (с задержкой ~10 мин), индекс страха/жадности,
история реакций рынка на похожие события. Новость никогда не сигнал сама по себе — только фактор.
Нет данных — фактор помечен «нет данных» и не помогает оценке.

Ниже порога (60, настраивается) возможность скрыта (фильтр «Show low quality»), не уходит в Telegram
и не исполняется в AUTO. За 5 мин до важного релиза США — вход запрещён (вето).

**Обучение**: каждая возможность с NET ≥ 0.1 % торгуется виртуально (shadow) независимо от оценки —
с целью, стопом и окном. Во вкладке Stats → «Learning» видно, правда ли оценка A/B выигрывает чаще,
чем C/D. Веса оценки фиксированы; бот учит только измерения (не подгоняет параметры под прошлое).

**Плечо** — расчёт и совет, ордера с плечом не отправляются (твои биржи — спот). На карточке:
допустимое плечо (до 2× при оценке 70+, 3× при 80+, 5× при 90+), стоп, ликвидация, R:R; ограничения —
ликвидация не ближе 3 стопов, риск на сделку ≤ 0.5 % капитала, глубина стакана. Виртуальный P&L с
плечом — в Stats.

Опционально в `.env`: `COINGECKO_API_KEY` (бесплатный demo-ключ, чаще обновляет пул), `BLS_API_KEY`
(факты по рабочим местам/CPI), `ANTHROPIC_API_KEY` (точнее разбирает новости).

## Shadow trading и статистика

Каждая найденная возможность автоматически торгуется **виртуально** по реальному стакану, без ордеров:
вход по VWAP на момент сигнала, выход по реальной цене, когда биржа догнала цель или окно закончилось.
Результат минус комиссии и потери исполнения. Вкладка **STATS** показывает итоги реальных сделок
(ожидаемый и фактический NET, win rate, P&L), итоги shadow и стратегию по бирже и монете.
Выключить: `shadow_trading = false` в `config.json`. Отчёт приёмки — `ACCEPTANCE.md`.

Как читать STATS:
* **Тренировка на неограниченных деньгах** (по умолчанию, `shadow_unlimited`): баланс не проверяется,
  каждая виртуальная сделка идёт на лучший размер для стакана (до 50× суммы карточки). В Stats —
  «Virtual P&L (unlimited stakes)», средний NET и просадка по сумме NET % (не зависит от размера).
* **Ограниченный виртуальный счёт** (галочку снять): сделки берут сумму из свободного баланса
  `shadow_balance_quote` (по умолчанию 1000); лучший размер не помещается — берётся сумма карточки;
  не помещается и она — «no free virtual balance». New period начинает баланс заново.
* **Период.** Итоги считаются с начала периода (строка «Period: since …»). Кнопка **New period**
  начинает новый отсчёт; старые сделки остаются в истории и в базе.
* **Best NET** в таблице сделок — лучший NET за время сделки. Если он был в плюсе, а итог в минусе —
  поздний выход. Если всегда в минусе — биржа просто не догоняет (ложный лаг).
* **Догон учится на каждом эпизоде.** Если биржа по монете ни разу не догнала, ожидаемый догон для этой
  пары становится 0 и бот перестаёт показывать по ней «прибыль». Если пара снова начнёт догонять,
  догон вернётся сам. В DIAG это видно как «catch-up x0.00».

## Spot-Futures арбитраж (вкладка Basis): исследование, только виртуально

Отдельный модуль рядом с ботом: ничего в основной стратегии не меняет и **никогда не отправляет ордера**.
На самых торгуемых биржах (Binance, OKX, Bybit, MEXC, Gate, Bitget; по выбору также HTX и Kraken + Kraken Futures)
он смотрит стаканы спота и бессрочного фьючерса
одной монеты в одной валюте (USDT, у Kraken — USD) и считает:

* **базис** — разница фьючерса и спота (в деньгах и в %), его историю;
* **базис по сторонам стакана** — вход: купить спот по ask + продать фьючерс по bid; выход: наоборот,
  на объём `basis_notional_quote` (проход по стакану, проскальзывание);
* **потенциальный NET** — после 4 комиссий taker и ожидаемого funding.

Данные только свежие и синхронные: оба стакана моложе `basis_max_age_ms` и не дальше друг от друга, чем
`basis_max_skew_ms`, иначе момент пропускается (счётчики «stale / timestamps apart»).

**Условия** (виртуальные, срабатывают в момент наступления): фьючерс дошёл до верхней границы
(`basis_fut_upper_pct` выше своего среднего за `basis_ref_window_s`), спот дошёл до нижней границы
(`basis_spot_lower_pct` ниже своего среднего).  `basis_mode`: `fut_upper`, `spot_lower`, `any` или `both`
(оба одновременно).

**Симулятор исполнения**: каждая нога исполняется через `basis_latency_ms` после сигнала по стакану того
момента; тонкий стакан даёт частичное исполнение, лишнее на одной ноге сразу закрывается (убыток
учитывается).  Если исполнилась только одна нога — это инцидент «one leg», он записывается отдельно и
**не считается** хеджированной сделкой.  Выход — когда базис сошёлся (до `basis_exit_basis_pct` и не меньше
чем на `basis_min_convergence_pct` ниже входа) или через `basis_max_hold_s`.  Funding начисляется шорту в
моменты выплат; неизвестная ставка помечается, а не угадывается.  Записывается наибольшее неблагоприятное
движение базиса.

**Тренировочные пары** (`basis_train_all_signals`, включено): каждый сигнал (фьючерс выше нормы, спот ниже
нормы или оба сразу) открывает виртуальную пару, даже если он не совпадает с `basis_mode`. Так плюсы и минусы
спота и фьючерсов попадают в статистику. Во вкладке Basis есть таблица результатов по типу сигнала и по паре
«биржа + монета». Из неё видно, что теряет и что зарабатывает. Режим и пороги бот сам не подгоняет: решение
по цифрам принимаешь ты.

**Вкладка Basis**: сигналы, исполненные пары, неполные исполнения, средний базис на входе и выходе,
валовой и чистый P&L, комиссии, funding, максимальное неблагоприятное движение, живые пары и список сделок.
Все параметры — в `config.json` (`basis_*`).  Выключить: `basis_enabled: false`.

### Сбор funding (carry): главный кандидат на заработок, пока виртуально

Купить спот и продать бессрочный фьючерс той же монеты на одной бирже. Цена монеты на результат не влияет:
сколько теряет одна нога, столько зарабатывает другая. Пока funding положительный, шорт получает выплату
каждые 1–8 ч.

* **Выгода** = funding за `carry_horizon_h` (72 ч) по текущей ставке − 4 комиссии − цена пересечения обоих
  стаканов сейчас (на объём `carry_notional_quote`).
* **Вход**: последние `carry_confirm_polls` (2) опроса funding положительные, а выгода не меньше
  `carry_min_edge_pct` (0.10 %). Одновременно не больше `carry_max_positions` (5) позиций, сначала самые выгодные.
* **Выход**: 2 опроса подряд ставка ниже `carry_exit_rate` (0), или прошло `carry_max_hold_h` (14 дней).
* **Надёжная ставка**: выгода считается по меньшей из двух ставок — текущей и средней за последние
  `carry_history_n` (21) выплат из истории биржи. Разовый всплеск входа не даёт. Монета, у которой
  положительных выплат меньше `carry_min_positive_share` (80 %), не берётся. Реальный интервал выплат
  (1/4/8 ч) берётся у биржи или из истории. Опросы ставки переживают перезапуск.
* **Умный выход**: при отрицательной ставке позиция закрывается, только если держать её `carry_exit_horizon_h`
  (24 ч) дороже, чем выйти (2 комиссии + спред). Небольшой минус бот пережидает.
* **Капитал и ликвидация**: под шорт нужен залог, плечо `carry_leverage` (2x). Капитал = спот + залог, и
  годовая доходность (APR) считается от всего капитала. Для шорта считается цена ликвидации
  (`carry_maint_margin` 0.5 %). Если цена подошла к ней ближе `carry_liq_guard_pct` (5 %), пара закрывается
  заранее. Если цена перескочила ликвидацию, весь залог считается потерянным, а спот продаётся.
* Позиция переживает перезапуск бота. Funding за время, пока бот был выключен, не считается, и позиция
  помечается «funding unknown».
* Блок **FUNDING CARRY** во вкладке Basis показывает открытые позиции, собранный funding, комиссии, чистый
  результат и годовую доходность (APR). Колонка «Carry edge» в таблице пар — текущая выгода; «?» значит,
  ставка ещё не подтверждена. Все ставки пишутся в таблицу `funding_samples` базы для анализа.

Биржи по умолчанию (`basis_venues`): Binance, OKX, Bybit, MEXC, Gate, Bitget — у них самый большой объём
спота и фьючерсов. HTX (спот 0.2 %) и Kraken (спот 0.4 %) можно добавить вручную. Если биржа недоступна, она
просто пропускается. Funding опрашивается по всем биржам одновременно, одним запросом на биржу, где это возможно.

План: 1–2 недели виртуально на твоём ПК. Дальше решаем по цифрам, включать ли
реальные сделки малым объёмом.

### Межбиржевой funding: лонг там, где ставка низкая, шорт там, где высокая (виртуально)

Одна монета, два вечных фьючерса на разных биржах. На бирже, где funding ниже, бот открывает лонг, на бирже,
где выше, — шорт. Цена монеты на результат не влияет, в плюс идёт разница выплат. Данные берутся из того же
модуля Basis: стаканы фьючерсов, комиссии, опросы и история funding.

* **Выгода** = разница ставок в час × `xfund_horizon_h` (72 ч) − 4 комиссии (вход и выход на обеих биржах) −
  спреды обоих стаканов на объём `xfund_notional_quote` − ценовой разрыв, если на бирже лонга цена выше
  (при выравнивании цен он уйдёт в минус). Ставки берутся осторожно: для шорта меньшая из текущей и средней
  по истории, для лонга большая.
* **Вход**: разница положительная 2 опроса подряд, выгода не меньше `xfund_min_edge_pct` (0.10 %). Одна пара на
  монету, не больше `xfund_max_positions` (5), сначала самые выгодные. Вход только по свежим синхронным
  стаканам, выгода пересчитывается перед входом.
* **Выход**: разница ушла в минус и держать позицию `xfund_exit_horizon_h` (24 ч) дороже, чем выйти; или
  `xfund_max_hold_h` (14 дней); или одна из ног подошла к ликвидации ближе `xfund_liq_guard_pct` (5 %).
* **Капитал** = залог на обеих биржах (плечо `xfund_leverage` 2x). Годовая доходность (APR) считается от
  капитала. Исполнилась только одна нога — это инцидент, а не сделка.
* Во вкладке Basis: блок **CROSS-VENUE FUNDING**, таблица лучших пар сейчас и список виртуальных пар.

### Импульс на BTC и ETH (фьючерсы, лонг и шорт, виртуально)

Бот заходит в движение: монета выросла (или упала) за 15 минут, и часовой тренд в ту же сторону.
Заходит на вечном фьючерсе по живому стакану, с комиссией, задержкой и проскальзыванием.

* **Вход**: движение за `mom_window_s` (15 мин) не меньше `mom_entry_pct` (0.6 %) и за `mom_trend_s` (1 ч) не
  меньше `mom_trend_pct` (0.3 %) в ту же сторону. Рост — лонг, падение — шорт. Одна позиция на монету, после
  выхода пауза `mom_cooldown_s` (15 мин). Размер `mom_notional_quote` (1000), плечо 1x.
* **Выход** по рынку:
  * жёсткий стоп `mom_stop_pct` (0.5 %) от цены входа;
  * трейлинг-стоп `mom_trail_pct` (0.4 %) от лучшей цены — включается, когда позиция была в плюсе хотя бы на 0.4 %;
  * лимит времени `mom_max_hold_s` (1 ч).
* Цены берутся с одной биржи (первая доступная из `mom_venues`: Binance, Bybit, OKX, MEXC, Gate, Bitget).
  Цены разных бирж в одно движение не смешиваются. Нет свежего стакана — нет входа. Позиция без свежей цены
  60 с закрывается как «нет данных», результат не выдумывается.
* Первые 45–60 минут после запуска бот копит историю цен («warming up») и не входит.
* Во вкладке Basis: блок **MOMENTUM** (сделки, процент прибыльных, средний NET, P&L, лонги и шорты отдельно,
  просадка), текущие движения BTC и ETH за 15 мин и 1 ч, список сделок.

### Hyperliquid и плечо в межбиржевом funding

* **Hyperliquid** (`basis_perp_venues`) подключён как биржа только с фьючерсами. Funding там платится каждый
  час и часто отличается от Binance, Bybit и OKX. Бот берёт только публичные данные: кошелёк и ключи не нужны.
* Фьючерсы Hyperliquid считаются в **USDC**, у остальных бирж в USDT. Такие пары помечены «USDT vs USDC»: в
  результат входит курс USDC к USDT. Разрыв цен против пары бот учитывает как расход.
* На Hyperliquid нет спота в боте, поэтому Basis и carry там не считаются.
* **Плечо** `xfund_leverage`: от 1 до 5, по умолчанию 2. Больше плечо — меньше залога и выше доходность на
  капитал, но ликвидация ближе: при 2x около 49.5 % движения цены, при 5x около 19.5 %. Защита закрывает пару,
  когда до ликвидации остаётся `xfund_liq_guard_pct` (5 %). На резком скачке цена может перескочить защиту,
  тогда залог одной ноги теряется полностью.

### Лимитные ордера (maker) в funding-стратегиях

`carry_exec` и `xfund_exec`: `"maker"` (по умолчанию) или `"taker"` (всё по рынку, как раньше).

* Одна нога ставится лимитным ордером на своей стороне стакана (покупка по лучшему bid, продажа по лучшему
  ask) и платит комиссию maker. Выбирается нога, где maker экономит больше. Вторая нога сразу после
  исполнения первой закрывается по рынку, чтобы не остаться с одной стороной.
* Лимитный ордер считается исполненным, только когда цена **прошла сквозь** него. Касание цены исполнением
  не считается: место в очереди неизвестно.
* Вход не исполнился за `maker_wait_s` (60 с) — ордер снимается, сделки нет, расходов нет. Выход, который не
  исполнился лимиткой, уходит по рынку. Выход у порога ликвидации всегда по рынку.
* Если комиссия maker у биржи не ниже taker или неизвестна, бот торгует по рынку.
* Экономия зависит от биржи: одна нога всё равно идёт по рынку. Комиссии maker по умолчанию — базовый тариф
  биржи; с ключами бот берёт твой реальный тариф.

## Журнал сделок и скриншоты

В таблице TRADES у каждой сделки есть **JOURNAL**: заметка, загрузка скриншота экрана биржи (PNG/JPEG/WEBP,
до 8 МБ, хранится в `data/screenshots/`) и кнопка **ANALYZE** - разбор сделки по скриншоту и цифрам из
журнала через Claude. Для разбора нужен `ANTHROPIC_API_KEY` в `.env`; без ключа кнопка отключена и так и
написано (NOT AVAILABLE), фальшивого результата не будет. Модель - `analysis_model` в `config.json`.
