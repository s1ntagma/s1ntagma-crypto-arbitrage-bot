# Мониторинг Telegram

Токен лежит в `.env`: не читать, не печатать, не вставлять в команды. Сообщения от имени владельца не отправлять.

## Как должно работать

- Владелец - `TELEGRAM_CHAT_ID` из `.env` или кто первым написал `/start`; хранится в базе (kv `telegram_chat_id`).
  Остальные чаты игнорируются. Нажатия, сделанные пока бот был выключен, не выполняются.
- Алерт уходит, только если `net_pct >= telegram_profit_threshold_pct` (3 %) и хотя бы один светофор не красный.
  Один алерт на `opportunity.id`; обновления - редактированием сообщения не чаще раза в 3 с;
  при EXPIRED/CLOSED - финальная правка с длительностью или фактическим NET.
- Кнопка `OPEN OPPORTUNITY` ведёт на `public_url/#opp/<id>` - карточка открывается сразу.
- Без запроса - только важное: алерт, открытие/закрытие сделки, EMERGENCY, обрыв и возврат связи с биржей,
  запуск и остановка. Возможности на 0.5-2 % в Telegram не идут - они в UI.
- Команды: `/status`, `/stop` (с подтверждением кнопкой), `/resume`, `/human <сек>`, `/threshold <%>`, `/mode`, `/help`.
  Режим PAPER/LIVE из Telegram не переключается.

## Как проверить

```
python -m pytest -q tests/test_telegram.py
findstr /c:"telegram" logs\console.log
```

- В логах метод (`sendMessage`, `editMessageText`), но никогда не URL с токеном.
- «Conflict» в ответе Telegram - тем же токеном пользуется другая программа (например, старый бот).

## Чего не делать

- Не добавлять уведомления о каждом обновлении карточки или каждом отказе: это спам.
- Не опускать порог алерта ниже 3 % без решения владельца.
